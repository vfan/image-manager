# PNG 图库（ImageManager）

一个轻量的 macOS 原生桌面应用：**选一个目录**（随时可更换），自动扫描其中所有 PNG，**按尺寸分类**展示——默认就按「精确像素尺寸」分组，比如 `2048 × 2048` 一组、`1920 × 1080` 一组。选中某一尺寸后，右侧再**按子目录分类**，比如这个尺寸在 `A/`、`B/`、`C/` 里各有多少张。

- 原生 SwiftUI + AppKit，**2.6 MB** 安装体积，启动即用（不打包 Chromium、无第三方依赖）
- 十万张级别目录也能流畅滚动：虚拟化网格 + 缩略图磁盘缓存 + 增量刷新
- 扫描只读 PNG 文件头，不解码大图

## 快速开始

```bash
./scripts/build-app.sh --open     # 构建并启动 build/ImageManager.app
./scripts/build-app.sh --install  # 构建并安装到 /Applications
./scripts/smoke.sh ~/Pictures     # 对任意目录跑端到端冒烟测试（打印分类统计）
swift test --disable-sandbox      # 单元测试
```

> 本机 SwiftPM 的默认 `TMPDIR` / 模块缓存不可写，构建脚本会自动把缓存放到仓库内 `.cache/`。

## 功能

| 功能 | 说明 |
|---|---|
| 选择目录 | 按钮、⌘O 或**直接把文件夹拖进左侧边栏**；只有一个当前目录，再次选择即替换（不会累积成列表） |
| 扫描 | 递归扫描子目录，按文件内容（PNG 签名）识别，不看扩展名；隐藏文件、符号链接跳过 |
| 按尺寸分类 | **默认按精确像素尺寸**（`1024 × 1024 × 37`）；侧边栏或工具栏可切换成**宽高比**（16:9 / 1:1 / 9:16 …）、**宽度档位**、**像素面积档位** |
| 浏览 | 选中目录时按尺寸分组；选中某个尺寸/比例组时**按子目录分组**（`A/`、`B/`、`C/`、根目录）。每组一次展示全部图片，每行张数随窗口宽度和缩略图缩放自适应；也可切换连续网格、调整缩略图大小（⌘+ / ⌘-） |
| 排序 | 名称、宽→竖、像素多→少、文件大小、修改时间 |
| 搜索 | 文件名 / 相对路径 / `1920x1080` 尺寸词，可组合空格分词 |
| 详情 | 选中后在右侧检查器显示尺寸、宽高比、所属分类、位深、色彩类型（是否含透明通道） |
| 预览 | 空格/工具栏快速查看，双击用默认应用打开，右键菜单复制路径/尺寸 |
| **多选 / 圈选** | ⌘-点击加选、⇧-点击选一段，或在空白处拖出一个框把经过的图全选上；状态栏显示“已选 N 张” |
| **删除** | 右键「删除（移到废纸篓）」或按 ⌫；多选时一次删整批，操作前确认；删的是真的移到废纸篓，可以恢复 |
| **分组备注** | 给某个尺寸或比例写个名字（如 `1170 × 2532 → iOS 截屏`），备注显示在左侧列表和分组标题上，还能直接搜到 |
| **列表筛选** | 工具栏左上角漏斗：`小于100 / 小于300 / 大于300 / 大于500 / 大于1000` 一键筛左侧尺寸列表（右侧图片不受影响）；也可自定义长边/短边/宽/高，条件自动存盘 |
| 自动刷新 | FSEvents 监听目录，新增/删除/修改 PNG 时增量更新，不重扫全盘 |
| 二次启动 | 先用上次的索引秒开，并**直接回到上次选中的那一行**（目录或某个尺寸组）；随即后台重扫，界面边扫边刷新 |
| 不再有“全部图片” | 侧栏只有目录和尺寸/比例分组，没有把整库平铺的入口——那正是最容易卡死的视图 |

## 分组备注

某一组尺寸/比例认不出来？右键给它起个名字：

- 左侧列表里**右键任意尺寸或比例** → 「添加备注…」，输入 `iOS 截屏` 之类，保存后：
  - 备注显示在左侧列表该行的标题下面（气泡图标 + 文字）
  - 主区域同名分组的标题旁也会显示
  - 已经带备注的组，右键变成「编辑备注…／删除备注」
- 主区域分组标题右侧的 💬 按钮同样可以直接加。
- 备注按「分组方式 + 具体值」分别保存：`2048 × 2048`（尺寸）和 `1:1`（比例）可以各写各的。
- **搜索备注也能筛图**：搜「iOS」会把备注含 iOS 的那一组图片全部筛出来。
- 有备注的小尺寸组（张数不到侧栏阈值）也会被保留显示，不会出现“写了备注却找不到”的情况。

保存位置：`~/Library/Application Support/com.local.ImageManager/notes.json`。

## 默认分组方式

打开就是「按尺寸」分组：同一像素尺寸的图归到一组，组标题是 `宽 × 高`，按图片数量从多到少排列。想换成比例分组，用两处任意一处切换，选择会被记住并作为下次的默认：

- 侧边栏「按尺寸分类」标题右侧的滑杆按钮
- 工具栏的「按尺寸」菜单

## 列表筛选（只收窄左侧列表）

左侧的尺寸/比例多了以后不好找。工具栏**最左边**的漏斗按钮（或 ⇧⌘F）把左侧列表收窄——右侧图片完全不受影响。

弹出来就五个常用档，点一下即生效，再点一下取消：

| 按钮 | 长边范围 | 用途 |
|---|---|---|
| 小于 100 | ≤ 100 px | 只留超小图标 |
| 小于 300 | ≤ 300 px | 小图标、表情包素材 |
| 大于 300 | ≥ 300 px | 去掉小图标 |
| 大于 500 | ≥ 500 px | 只看正常尺寸以上 |
| 大于 1000 | ≥ 1000 px | **只看大图** |

- **只作用于左侧列表**：被筛掉的只是侧栏里的那些行；右侧仍显示当前范围的全部图片，点开某一行也照常看到该组所有图。
- 行数实时显示：“左侧剩 23 / 29 组”；侧栏顶部会出现“列表已筛选 23/29 组”的提示条，随时调整/清除。
- 需要精细条件时点「更多条件…」：长边/短边/宽/高四个维度设上下限，单位 px / K / dp，可选只看横图/竖图；面板里实时预览行数，`应用` 落盘、`取消` 还原、`清除` 归零。
- 筛选后一组都不剩时，侧栏会提示并给“清除列表筛选”按钮。
- **会记下来**：条件存进 `filters.json`，下次打开自动恢复（连同草稿和最近用过的尺寸组合）。

诊断用命令行也支持：

```bash
.build/debug/ImageManager --add-folder ~/Pictures \
  --filter "longSide>=1000" --scan-and-export /tmp/report.json   # 报告含 groupCount / hiddenGroups
```

## 按子目录查看与移动文件

左侧选中某个尺寸/比例时，右侧按**子目录**分段：`A/` 32 张、`B/` 18 张、`C/` 5 张，根目录里的图单独一段。只有含这个尺寸的子目录才出现，空的不会占位。

想清理某个尺寸的图：左侧点 `500 × 500` → 右侧一段段看 → 把不要的挪到别的子目录。

### 移动只能到“当前列表里出现的子目录”

- **拖拽**：把缩略图拖到另一段的标题或那一行上，松手即移动，目标段会高亮提示。
- **右键 → 移动到子目录**：只列出允许的目标。
- 规则：目标子目录必须**在当前右侧列表里出现过**。选中 `500 × 500` 时右侧只有 A、B、C 三段，那 C 里的图只能去 A 或 B；D 里没有这个尺寸，不作为候选，菜单里不出现，拖过去也不接收。
- 不能移动到它自己所在的子目录；根目录里的图可以进任何列出的子目录。
- 不覆盖同名文件：自动改名 `shot 2.png`、`shot 3.png`。
- 移动是真实文件操作，索引同步更新（新路径、新所在子目录），右侧分段和计数立即重排，状态栏提示“已移动 1 张到「A」”。
- 只接受当前列表里的图（从访达拖进来的无关文件不会被搬走）。

## 多选与删除

- **⌘-点击**：加选/取消单张；**⇧-点击**：从上次点的那张到这张整段选中（前后都行）。
- **圈选**：在空白处按住拖动，拉出一个虚线框，框到的缩略图全部选中；从缩略图上开始拖仍然是「拖到子目录去移动」，两种操作不会打架。
- 状态栏会显示“已选 N 张”。
- **删除**：右键菜单「删除（移到废纸篓）」，或按 ⌫（文件菜单里也有）。多选时一次删整批，先弹确认；单张直接删。
- 删除是 `trashItem`，文件进废纸篓可恢复，不是 `rm`。删完索引、侧栏计数、右侧分段立刻更新。
- 切换尺寸/目录、搜索、筛选时自动清空选区，避免误删看不见的图。

## 技术方案（为什么快）

| 环节 | 做法 | 实测（Apple Silicon，/tmp 上的 2000 个文件） |
|---|---|---|
| 读尺寸 | `open` + 一次 33 字节 `pread` 读 IHDR，`fstat` 顺带拿文件大小/修改时间 | **0.06 – 0.09 ms / 张** |
| 遍历 | `FileManager.enumerator` + `skipDescendants` | 流式回调，边扫边显示进度 |
| 缩略图 | ImageIO 解码 → 直接绘制进 320px 的小 `CGContext`（比 `CGImageSourceCreateThumbnailAtIndex` 快约 35%） | 1080p ≈ 17 ms，4000×3000 ≈ 92 ms |
| 缓存 | 索引 `index.json`（路径/尺寸/大小/时间，启动直接复用，未变化的文件不读头）+ 内存 LRU（`NSCache`，~96 MB）+ 磁盘 PNG 缓存（键 = 路径+修改时间+大小） | 热启动 100% 复用索引；缩略图二次打开 2–4 ms |
| 渲染 | `LazyVGrid` / `LazyVStack` 只实例化可见单元；缩略图异步加载，永不阻塞主线程 | 视图层始终只保留几十个 cell |
| 刷新 | FSEvents 1.5 秒防抖，只重新读取变化的路径 | 不整目录重扫 |

并发模型：`AppStore`（`@MainActor`）是唯一状态源；扫描在 `Task.detached` 里跑，通过线程安全的缓冲每 120 ms 批量汇入 UI；缩略图在独立并发队列生成。

## 已知限制

- 目前只支持 PNG（Alpha/调色板/灰度都行；APNG 按首帧显示）。其他格式可复用同一管线扩展。
- 列表筛选按像素尺寸判断；比例类条件（如超宽 2.39:1）请用左侧“宽高比”分组，或对长/短边分别设限。
- 开发签名为 ad-hoc：首次打开若提示“无法验证开发者”，右键 → 打开即可。
- 截图用 `--snapshot` 依赖窗口在屏幕上可见；无图形会话（SSH / CI）下只能跑 `--scan-and-export` 与单元测试。
